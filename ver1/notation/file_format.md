# Формат файлов нотаций `.json`

Каждая нотация wArchi2-JS хранится в отдельном файле в каталоге
`ver1/notation/`. Это требуется пунктом 4 задания: «храни каждую нотацию
в отдельном файле, опиши формат и формализм правил метамодели».

## Назначение

* Один файл = одна нотация (ArchiMate, C4, BPMN, UML и т. п.).
* Файл описывает: имя, версию, элементы (типы узлов), теги, типы связей и
  правила метамодели — то есть формальные ограничения, которые проверяет
  редактор.
* Файлы человекочитаемые (UTF-8 JSON) и пригодны для diff в git.

## Расширение и MIME

| Расширение | MIME                          | Кодировка |
|------------|-------------------------------|-----------|
| `.json`    | `application/json+notation`   | UTF-8     |

## Структура файла

```jsonc
{
  "format": "warchi-notation",
  "formatVersion": "1.0",

  "id": "n-archimate",
  "name": "ArchiMate",
  "fullName": "ArchiMate 3.1",
  "version": "3.1.0",
  "icon": "🏛️",
  "description": "Стандарт архитектурного описания предприятия (The Open Group).",

  // Элементы (типы узлов).
  "elements": [
    { "id": "goal",    "name": "Цель",    "icon": "🎯", "layer": "Мотивация" },
    { "id": "process", "name": "Процесс", "icon": "📋", "layer": "Бизнес"    }
  ],

  // Теги для фильтрации/группировки элементов в палитре.
  "tags": ["Strategy", "Motivation", "Business", "Application", "Technology"],

  // Типы связей (отношений).
  "linkTypes": [
    { "id": "flow",    "name": "Поток",     "style": "solid",  "arrow": "end" },
    { "id": "trigger", "name": "Триггер",   "style": "dashed", "arrow": "end" }
  ],

  // Правила метамодели (формальные ограничения).
  "rules": [
    {
      "id":       "no-self-loops",
      "kind":     "link",
      "predicate": "source != target",
      "message":  "Связь не может вести из узла в самого себя"
    },
    {
      "id":       "trigger-direction",
      "kind":     "link",
      "predicate": "linkType == 'trigger' implies direction == 'directed'",
      "message":  "Триггер обязательно ориентированный"
    }
  ]
}
```

## Формализм правил метамодели

Поле `rules[]` использует упрощённый декларативный язык предикатов
первого порядка. Каждое правило состоит из:

| Поле       | Назначение                                                     |
|------------|----------------------------------------------------------------|
| `id`       | Уникальный идентификатор правила внутри нотации                |
| `kind`     | На что распространяется: `node` / `link` / `model`             |
| `predicate`| Логическое условие, которое должно быть истинным               |
| `message`  | Сообщение об ошибке, если предикат не выполняется              |

### Допустимые операторы предикатов

| Оператор   | Семантика                                       |
|------------|-------------------------------------------------|
| `==`, `!=` | Равенство / неравенство                          |
| `&&`, `||` | Логическое И / ИЛИ                               |
| `!`        | Логическое НЕ                                    |
| `implies`  | Импликация (из левого следует правое)            |
| `in`       | Принадлежность множеству: `nodeType in {...}`    |
| `count(x)` | Количество элементов выборки `x`                 |
| `exists`   | Существует хотя бы один элемент, удовлетворяющий |
| `forall`   | Все элементы выборки удовлетворяют               |

### Допустимые сущности и поля

* `node` — узел: `id`, `name`, `nodeTypeId`, `layer`, `tags[]`.
* `link` — связь: `id`, `source`, `target`, `linkType`, `direction`,
  `tags[]`. `source` и `target` — это узлы, к которым правило обращается
  через точку (`source.layer`, `target.nodeTypeId` и т. п.).
* `model` — модель: `id`, `notationId`, `nodes[]`, `links[]`.

### Пример с импликацией

```jsonc
{
  "id": "data-access-direction",
  "kind": "link",
  "predicate": "linkType == 'access' implies target.nodeTypeId == 'nt-data'",
  "message": "Связь «Доступ» должна вести К объекту данных"
}
```

## Загрузка

```js
fetch('notation/n-archimate.json')
  .then(r => r.json())
  .then(file => DB.notations.push(file));
```

При запуске через GitHub Pages (`https://`) `fetch()` работает корректно;
при открытии `index.html` напрямую (`file://`) браузер блокирует `fetch`
из-за CORS, поэтому встроенные нотации дублируются в `defaultData()`.
