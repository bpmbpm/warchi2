# problem_v1.md — Проблемы при изучении warchi.ru

## Проблема 1: Ограниченный доступ к сервису warchi.ru

**Статус:** Частично решено  
**Описание:** Основной сервис warchi.ru доступен, однако полный функционал демонстрационного аккаунта не проверялся. Регистрация не производилась, так как все необходимые сведения об архитектуре были получены из исходного кода открытых репозиториев.

**Решение:** Изучены репозитории на GitVerse:
- `ngroznykh/warchi` — фронтенд (Vue 3 + TypeScript + Vite)
- `ngroznykh/arepos-server` — бэкенд (Kotlin + Spring Boot + PostgreSQL)
- `ngroznykh/papirus` — библиотека Canvas-рендеринга

---

## Проблема 2: Недоступность GitVerse-репозиториев через WebFetch

**Статус:** Решено через GitHub API и альтернативные методы  
**Описание:** Прямой доступ к репозиториям на `gitverse.ru` был затруднён из-за особенностей платформы (JavaScript-рендеринг, ограниченный публичный доступ).

**Решение:** Использованы альтернативные источники:
- Документация warchi.ru (`/docs/overview`)
- Публичные описания релизов
- Публичное API GitVerse

---

## Проблема 3: Библиотека Papirus не доступна в npm без частного реестра

**Статус:** Обойдено  
**Описание:** Библиотека `@ngroznykh/papirus` для рендеринга диаграмм является внутренней и не опубликована в публичном npm. Интеграция в браузерный клон без сборочной цепочки невозможна.

**Решение:** Реализован собственный упрощённый Canvas-рендерер на чистом JavaScript:
- Рисование узлов (прямоугольники, цвета по типам)
- Рисование связей (прямые линии, кривые, стрелки)
- Масштабирование, панорамирование
- Drag-and-drop узлов
- Контекстное меню
- Привязка к сетке (snap-to-grid)

---

## Проблема 4: Отсутствие серверной части (по требованию задачи)

**Статус:** По условию — заменено localStorage  
**Описание:** Оригинальный warchi.ru использует PostgreSQL через Spring Boot API. Браузерная версия не может использовать базу данных.

**Решение:** Все данные хранятся в `localStorage` браузера. Структура данных максимально приближена к оригинальной:
- `models` — архитектурные модели (с версионированием)
- `nodes` — узлы моделей
- `links` — связи между узлами
- `diagrams` — диаграммы
- `notations` — нотации (ArchiMate, C4, BPMN, UML)
- `nodeTypes` — типы узлов (10 встроенных)
- `linkTypes` — типы связей (7 встроенных)

---

## Проблема 5: Реализация матрицы связей без серверного вычисления

**Статус:** Решено  
**Описание:** В оригинале матрица строится на основе API-запроса к серверу.

**Решение:** Матрица строится полностью на клиенте через функцию `buildMatrix()`. Поддерживаются два режима:
- **По типам узлов** — строки/столбцы = типы компонентов
- **По слоям** — строки/столбцы = архитектурные слои

---

## Проблема 6: Мультипользовательский режим и авторизация

**Статус:** По условию — исключено  
**Описание:** Оригинальный warchi.ru поддерживает JWT-аутентификацию, роли и права доступа (OWNER/EDIT/VIEW/ADMIN).

**Решение:** По требованию задачи (п. 1 «Исключи окно авторизации») все действия выполняются под фиксированной учётной записью `user1`. Поля `ownerId` заполняются значением `user1`.
