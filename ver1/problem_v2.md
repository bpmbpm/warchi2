## Открытые проблемы

### П1. Загрузка моделей и нотаций из файлов через `file://`

**Статус:** не решено по архитектурной причине  
**Описание:** Файлы `.warchi` (`ver1/dia/*.warchi`) и
`.json` (`ver1/notation/*.json`) хранятся отдельно по требованию пп. 3
и 4. Однако открытие `index.html` напрямую (двойной клик в проводнике,
схема `file://`) запрещает `fetch()` из соображений CORS, и в этом
режиме файлы прочитать нельзя.

**Текущее поведение:** при первом запуске встроенный `defaultData()`
заливает в `localStorage` точную копию всех моделей и нотаций.
Файлы в `dia/` и `notation/` служат «эталоном» для git-истории и
для запуска через GitHub Pages.

**Что нужно для полного решения:**
* Поднимать локальный HTTP-сервер (например,
  `python3 -m http.server`) — тогда `fetch()` отработает.
* Либо использовать build-шаг, который инлайнит JSON-файлы прямо в
  `defaultData()` (нарушит «без сборки»).

---

### П2. Локализация интерфейса (RU/EN/FR)

**Статус:** частично — переключатель есть, тексты не переведены  
**Описание:** Кнопки RU/EN/FR в шапке переключают значение
`localStorage.warchi_lang`, но физически тексты пока остаются на
русском. Полная локализация требует словаря строк и функции `t(key)`,
вызываемой во всех местах рендера.

**Объём работы:** ~120 строк UI-текста + ~30 строк документации.

---

### П3. Полная палитра ArchiMate 3.1

**Статус:** упрощённо  
**Описание:** В реальной нотации ArchiMate 3.1 ~50 типов элементов
(Resource, Capability, Outcome, Principle, Requirement, Constraint,
Meaning, Value, Stakeholder, Assessment …). В wArchi2-JS реализованы
10 ключевых типов, покрывающих основные сценарии моделирования.

**Что нужно:** расширить `defaultData().nodeTypes` и
`notation/n-archimate.json/elements`.

---

### П4. Проверка правил метамодели в редакторе

**Статус:** правила описаны, движок проверки не реализован  
**Описание:** Файлы `notation/*.json` содержат поле `rules[]` с
формальным описанием ограничений. Однако сам редактор
(`index.html`) пока не проверяет эти правила в момент создания
связей или сохранения модели.

**Что нужно:** реализовать модуль `validateModel(db, notation)`,
который парсит `predicate` и подсвечивает нарушения в правой панели
«Трасс.».

---

### П5. Многопользовательский режим и роли

**Статус:** конфигурация ролей есть, проверки прав в UI не везде  
**Описание:** В `config.js` объявлены роли `OWNER/ADMIN/EDIT/VIEW`
с описаниями. Однако кнопки «Удалить модель», «+ Создать модель»,
«+ Добавить тип» не блокируются для ролей `VIEW`. По условию задачи
п. 1 авторизация исключена, поэтому это ограничение оставлено
осознанно — но при появлении бэкенда потребуется повсеместная
проверка `WARCHI_CONFIG.role`.

---

### П6. Папирус и Composer

**Статус:** упрощённый Canvas-рендерер  
**Описание:** Оригинальный warchi.ru использует библиотеку
[`@ngroznykh/papirus`](https://gitverse.ru/ngroznykh/papirus) с
поддержкой композитных узлов (Composer/CompositeNode), сложных форм
и SVG-фильтров. wArchi2-JS использует собственный простой
рендерер: прямоугольники, овалы, круги, ромбы. Перенос Papirus
возможен только при наличии исходников или сборочной цепочки.

---

### П7. Версионирование моделей

**Статус:** только поле `version`  
**Описание:** В .warchi-файле есть поле `model.version`, но истории
изменений (diff между версиями) нет. Для полного аналога нужен
отдельный каталог `dia/.history/` с снапшотами.

---

### П8. Wiki и интегрированная документация

**Статус:** документация только встроенная, без Wiki-движка  
**Описание:** В оригинале warchi.ru работает совместно с
[`mdwiki-frontend`](https://gitverse.ru/ngroznykh/mdwiki-frontend) —
отдельным wiki-движком. В wArchi2-JS пункт меню «Вики» пока ведёт
в раздел Документация. Полноценная Wiki требует отдельного хранилища
страниц и markdown-редактора.

   GitHub Pages уже работает. В readme добавить инструкцию для
   локального запуска через `python3 -m http.server`.
2. Реализовать `validateModel()` — движок проверки правил метамодели.
3. Локализация интерфейса (i18n словари RU/EN/FR).
4. Расширить палитру ArchiMate до 30+ элементов.
5. Внедрить простую историю изменений модели.
